# 03 · 开发规范

> **这份文档是干什么的**
> 它规定"代码怎么写、文件怎么放、改动怎么记"。
> 目的是让这个项目**半年后回来看还能看懂**，也让接手的人不用猜。

---

## 一、最高原则

按重要性排序，冲突时上面的压过下面的：

1. **不破坏用户的东西** —— 这是启动器，用户硬盘里是**几百小时的游戏存档**。
   任何删除、覆盖操作都必须先确认、先备份
2. **不崩** —— 网络断了、文件被删了、游戏起不来，软件本身要活着并说清原因
3. **看得懂** —— 给非程序员写的项目，代码要能被人读懂，不要炫技
4. **改得动** —— 加一个功能不应该要动十个文件
5. **好看** —— 前四项都满足之后，再追求美观

---

## 二、目录职责

```
src/main/           主进程。唯一允许碰系统、碰硬盘、起进程的地方
  main.js             入口：窗口、生命周期
  paths.js            所有目录路径集中在这里
  mojang.js           版本清单、版本 JSON
  mirror.js           官方 ↔ 国内镜像地址转换
  downloader.js       下载引擎
  java.js             找 Java / 下 Java
  install.js          装一个版本
  launch.js           拼参数、起进程
  versions.js         版本管理：改名/备注、打开文件夹、删版本
  accounts.js         账号与离线 UUID
  settings.js         配置读写

src/preload/
  preload.js        安全桥。界面能用什么，全部在这里列出来

src/renderer/       界面。不许引入构建工具
  index.html          结构
  style.css           样式（颜色全部用 CSS 变量）
  app.js              交互逻辑

assets/             图标等静态资源
build/              打包用图标 + 安装脚本
docs/               标准文档
开发日志/            每天一份工作记录
```

**硬规矩**：`src/renderer/` 里的代码**不许**出现 `require`、`fs`、`child_process`、
`path` 这类东西。界面要用的数据，一律通过 `window.api.xxx()` 向主进程要。

## 三、命名规范

| 对象 | 规则 | 例子 |
|---|---|---|
| 文件名 | 小写英文，多个词用连字符 | `download-manager.js` |
| 变量 / 函数 | 小驼峰 | `downloadFile`、`totalBytes` |
| 常量 | 全大写下划线 | `MAX_CONCURRENT`、`MIRROR_HOST` |
| CSS 类名 | 小写 + 连字符，必要时用 `__` 分块 | `card__title`、`topbar__logo` |
| CSS 变量 | 小写 + 连字符 | `--card-border-hover` |

**界面文字一律中文，代码标识符一律英文。** 不要把中文写进变量名或函数名。

---

## 四、代码风格

- 缩进 **2 个空格**，不用 Tab
- 字符串用单引号 `'`
- 语句结尾**不写分号**（与「历史粘贴板」保持一致）
- 每行不超过 **100 个字符**
- 优先用 `const`，需要重新赋值才用 `let`，**不用 `var`**
- 比较一律用 `===`，不用 `==`

## 五、注释规范

**要写"为什么"，不要写"是什么"。**

```js
// ❌ 废话注释
i++ // i 加一

// ✅ 有用的注释：解释了决策原因
// 先下到 .part 临时文件，校验通过后才改名成正式文件。
// 否则网络断了会留下一个"看着像下好了、其实是半截"的 jar，
// 下次启动直接报一个莫名其妙的类找不到
```

**必须写注释的地方**：
- 所有跟外部接口打交道的地方（说明这是哪个接口、返回什么、有什么坑）
- 所有"看起来可以简化但其实是故意这么写"的地方
- 每个文件的顶部（说明这个文件负责什么）

## 六、安全红线（不许违反）

| 规矩 | 为什么 |
|---|---|
| `contextIsolation: true` 不许改成 false | 界面与主进程隔离，安全底线 |
| `nodeIntegration: false` 不许改成 true | 否则界面里的任意内容都能操作用户电脑 |
| 界面要用的能力，逐条写在 preload 里 | 白名单，看得见、审得清 |
| 渲染层不许用 `innerHTML` 插入外部内容 | 版本名、Mod 名都来自网络，直接插会执行恶意代码，**一律用 `textContent`** |
| **删除任何用户文件前必须二次确认** | 那是别人几百小时的存档 |
| **不许动用户游戏目录之外的文件** | 启动器只该管自己那摊事 |
| 下载的文件必须校验哈希后才算数 | 下坏了、被篡改了，要能发现 |
| **开发和用户环境的数据必须隔离** | 「历史粘贴板」项目为此踩过大坑：开发时清数据，把用户真实数据一起删了 |

## 七、Git 提交规范

**每完成一个里程碑，提交一次**。提交信息格式：

```
M<编号>: <做了什么>

<可选：补充说明为什么>
```

**提交前必须**：
1. `npm start` 能正常启动，没有报错
2. 界面能正常显示
3. 当天的开发日志已更新

## 八、文档维护规范

| 情况 | 要改哪个文档 |
|---|---|
| 需求变了（加/减/改功能） | **先改** `docs/01-需求说明.md`，再动代码 |
| 换了技术方案或加了新依赖 | 改 `docs/02-技术方案.md` |
| 改了代码风格或目录结构 | 改 `docs/03-开发规范.md`（本文档） |
| 调整了开发顺序 | 改 `docs/04-开发计划与执行步骤.md` |
| 完成了里程碑 | 更新 `docs/05-验收标准.md` 的勾选状态 |
| 改了数据存放方式 | 改 `docs/06-数据与隐私说明.md` |
| 每次开发结束 | 更新 `开发日志/<里程碑号>-<短名>.md` |

**文档不是一次写完就完事的**。发现文档和代码对不上，要立刻改文档——
**错的文档比没有文档更糟**。

## 九、开发日志规范

**一个里程碑一份日志**（2026-10-12 从"一天一份"改的：按天攒到 340 KB，开工翻起来又慢又贵）。
**每次开发结束前必须做，一次都不能漏。**

1. 打开**当前里程碑**那一份 `开发日志/<里程碑号>-<短名>.md`（如 `V2c-打洞接进房间流程.md`）；
   是**新里程碑**才按 `_模板.md` 新建，并往 `00-索引.md` 追加一行
2. 在末尾**追加**（不要覆盖），记四件事：**做了什么 / 结论 / 遇到什么问题怎么解决的 / 下一步做什么**
3. 日志写得**像人话**，不要只写"修复 bug"。要写清"什么现象、为什么会出现"

## 十、沟通规范

本项目的用户**不是程序员**。所以：

- 用中文，**避免专业术语**；必须用术语时紧跟一句人话解释
- 说技术决策时必须回答"**这对你意味着什么**"
- 汇报进度说"**你现在能看到什么、能做什么**"，不要说"我改了哪几个文件"
- 不确定就说不确定，不要用技术名词糊弄
- **做不到的事要第一时间说**（比如需要审批、需要花钱、依赖别人的服务器）

---

## 十一、一次只做一件事

**一次只推进一个里程碑。** 做完停下来，让用户看到效果、确认没问题，再进下一个。

理由：用户看不懂代码，只能通过"能不能用"来判断进度。一次做太多，
出了问题说不清是哪一步引起的，用户也没法给有效反馈。

## 十二、自动化测试的纪律

这个项目用 PowerShell 模拟操作做自测。以下几条是**上一个项目用血换来的**：

1. **每个脚本都要自己确认焦点**——两次命令之间焦点会跑掉，
   上一步还在我们的窗口上、下一步就发给了别的软件（曾把 `Ctrl+Shift+K`
   误发给 VS Code，那是"删除当前行"）
2. **不要发可能造成破坏的组合键**，测试用别处没绑定的组合
3. **造测试数据后先打印出来核对**——曾写反了测试数据，测试照样"通过"了，
   却根本没考验到要验的点。**测试通过得毫无意义，比失败更危险**
4. **点击目标不确定时，先悬停截图确认**（按钮会有 hover 高亮），
   或把目标画成十字线截出来看。估算坐标经常差 10~40 像素
5. **别用中文当命令行参数**——bash 传 UTF-8、Windows 工具收 GBK，
   中文名对不上会**静默匹配失败**，看起来像"这东西不存在"
6. **自动打字前先确认输入法状态**——2026-10-07 实测：用 SendKeys 打
   `MySurvival`，被系统的**中文输入法**接过去，存进去变成了 `M'y'Survival`、
   `test note 123` 变成 `test农特123`。**软件本身没问题，是测试工具翻车了**——
   但如果不核对存下来的数据，就会误以为"改名的功能坏了"。
   所以：自动打字用纯英文，或者先把输入法切到英文模式，打完**把结果打印出来核对**
