# 01 · 需求说明

> **这份文档是干什么的**
> 它记录"这个软件要做什么、不做什么"。任何功能改动，先改这份文档，再改代码。
> 判断一个功能该不该做，标准只有一个：**它写在这份文档里吗？**

---

## 一句话说明

**MC启动器**是一个运行在 Windows 上的 Minecraft Java 版启动器，
能下载游戏、登录账号、启动游戏、管理版本，目标是做到类似 PCL 的体验。

## 要解决的问题

官方的 Minecraft 启动器功能有限：不能方便地管理多个版本、装不了 Mod 加载器、
下载慢、界面复杂。这个软件把这些事收拢到一个**简洁、直观**的界面里。

---

## 一、开发范围（分两期）

| 期 | 目标 | 状态 |
|---|---|---|
| **第一期** | **能下载原版 → 离线登录 → 启动进游戏 → 基础版本设置** | 进行中 |
| 第二期 | Mod 生态（Modrinth 对接、装加载器、资源包/光影/数据包） | 未开始 |

**正版登录**卡在 Mojang 审批上（不是代码能解决的），等审批有结果再补。

## 二、功能需求

### 1. 账号

| 编号 | 需求 | 说明 |
|---|---|---|
| R1.1 | **离线登录** | 输入一个名字就能玩。第一期的唯一登录方式 |
| R1.2 | 正版登录 | 微软账号登录。**等 Mojang 审批，第二期后再补** |
| R1.3 | 离线皮肤 | 给离线账号设置自定义皮肤（需要皮肤站或本地渲染） |
| R1.4 | 记住账号 | 关掉软件再打开，账号还在 |
| R1.5 | 多账号切换 | 可以存多个账号，随时切换 |

### 2. 游戏下载与安装

| 编号 | 需求 | 说明 |
|---|---|---|
| R2.1 | 版本清单 | 列出所有可下载的原版版本（正式版 / 快照 / 远古版） |
| R2.2 | 筛选与搜索 | 按类型筛选，按版本号搜索 |
| R2.3 | 下载并安装 | 客户端 jar、libraries、assets、Java 运行时，全部自动下载 |
| R2.4 | 完整性校验 | 每个文件下载后核对官方提供的哈希值，下坏了能发现 |
| R2.5 | 断点续传与重试 | 网络中断、单个文件失败都能自动重试，不用从头来 |
| R2.6 | **镜像自动切换** | 先连官方源，太慢就自动换国内镜像 |
| R2.7 | 进度显示 | 显示总进度、下载速度、剩余时间；能暂停和取消 |
| R2.8 | **自动下载 Java** | 版本需要哪个 Java 就下哪个，用户不用自己装 |

### 3. 启动游戏

| 编号 | 需求 | 说明 |
|---|---|---|
| R3.1 | 启动游戏 | 拼装正确的启动参数，把游戏跑起来 |
| R3.2 | 启动前检查 | 缺文件、缺 Java、内存设置不合理，要提前告诉用户 |
| R3.3 | 游戏日志 | 把游戏输出抓回来，启动失败时能看清原因 |
| R3.4 | **报错说人话** | 把游戏的一堆英文报错翻译成中文提示 + 常见原因 |

### 4. 启动设置

| 编号 | 需求 | 说明 |
|---|---|---|
| R4.1 | **内存分配** | 设置给游戏多少内存。显示本机总内存，给出建议值并限制上限 |
| R4.2 | **窗口大小** | 游戏窗口的宽高，或全屏 |
| R4.3 | **版本隔离** | 每个版本用独立的存档/Mod 目录，互不干扰 |
| R4.4 | **进程优先级** | 游戏进程的优先级（低 / 中 / 高） |
| R4.5 | 游戏目录 | 可以指定游戏装在哪，默认 `%APPDATA%\.minecraft` |
| R4.6 | 自定义启动参数 | 高级用户手动追加 JVM 参数 |

### 5. 版本管理

| 编号 | 需求 | 说明 |
|---|---|---|
| R5.1 | 已装版本列表 | 列出本机装好的所有版本 |
| R5.2 | 修改版本名 | 改显示名称 |
| R5.3 | 修改版本描述 | 加一句备注 |
| R5.4 | **快捷打开文件夹** | 一键打开「版本 / 存档 / Mod / 截图」四个文件夹 |
| R5.5 | 删除版本 | 删掉不要的版本（**必须二次确认**） |

### 6. 导出整合包

| 编号 | 需求 | 说明 |
|---|---|---|
| R6.1 | 勾选导出内容 | 像 PCL 那样，逐项勾选要导出什么 |
| R6.2 | 打包成文件 | 生成一个整合包文件，别人能导入 |
| R6.3 | 可选项 | 游戏本体设置 / Mod / 资源包 / 光影包 / 存档 / 截图 等 |

### 7. **跨局域网联机**（用户新增需求）

| 编号 | 需求 | 说明 |
|---|---|---|
| R7.1 | 和好友联机 | 两个不在同一个局域网的人，能像在同一个局域网里一样联机 |
| R7.2 | 房间码 | 房主创建房间得到一个码，好友输码加入 |
| R7.3 | 走现成方案 | 用 **EasyTier**（开源免费的异地组网）。PCL 2 的联机用的就是它 |
| R7.4 | 自动兜底 | 先尝试点对点直连，连不上自动走中继服务器 |
| R7.5 | 状态可见 | 显示连接状态、延迟、是直连还是走了中继 |
| R7.6 | 自动装组件 | 首次使用时自动下载并配置 EasyTier，用户不用自己折腾 |
| R7.7 | **主界面有入口** | 顶栏加一个「联机」页面，里面两件事：**创建房间**（生成一个房间码给人）和**加入房间**（输入别人的房间码）。另有一块显示连接状态 |

> **关于 R7 的三个现实情况（写下来避免以后意外）**
> 1. **需要管理员权限** —— EasyTier 要装一个虚拟网卡，Windows 会弹权限确认
> 2. **中继节点靠社区贡献** —— 打洞失败时走的中继服务器是别人无偿提供的，
>    稳定性和速度取决于节点状态。这是整个方案里最不可控的一环
> 3. **排在第二期之后** —— 它是个独立的大模块，先把"能玩游戏"做扎实

### 8. 界面

| 编号 | 需求 | 说明 |
|---|---|---|
| R8.1 | 简洁直观 | 不需要看说明书就会用 |
| R8.2 | **渐变淡蓝** | 主色调为渐变的淡蓝色 |

## 三、明确"不做"的事（范围边界）

这些是**有意不做**的，不是遗漏。如果以后要做，先加进这份文档再动手。

| 不做的功能 | 原因 |
|---|---|
| **CurseForge 作为下载源** | 要 Overwolf 人工审核，且条款**明令禁止**把 API 密钥内嵌进启动器。合规做法是自己架服务器转发，个人项目不现实 |
| **MC百科作为下载源** | 查证过：**没有官方下载接口**。非官方爬取有合规风险，而且 MC百科自己的下载页也是跳转到别处 |
| 「星叶云联」 | 用户未能提供资料，查不到公开接口。**先不做** |
| 读用户现有的 PCL 游戏目录 | 用户选择"各玩各的"，避免互相干扰 |
| 正版登录（第一期） | 卡在 Mojang 对第三方启动器 client_id 的审批，不是代码问题 |
| 内置服务器 / 开服功能 | 范围外 |
| Mac / Linux 版 | 只做 Windows |
| 自动更新启动器 | 第一版不做，用户手动下载新安装包 |

| 窗口大小 | 854 × 480（游戏默认） | |
| 版本隔离 | 开 | |
| 进程优先级 | 中 | |
| 下载并发数 | 8 | |
| 优先下载源 | 官方，太慢自动切镜像 | |
