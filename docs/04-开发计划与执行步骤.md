## 黄金法则

> **一次只推进一个里程碑。做完停下来给用户看，确认了再进下一个。**

用户看不懂代码，只能靠"能不能用"判断进度。一次做太多，出问题说不清是哪一步引起的。

## M2 · 版本清单

**目标**：从 Mojang 拉到版本列表并显示出来。

**步骤**
1. `src/main/mojang.js`：下载版本清单（`version_manifest_v2.json`）
2. 缓存到本地，**下次启动先显示缓存、后台再更新**（不联网也能看到列表）
3. `src/main/mirror.js`：官方 ↔ BMCLAPI 的地址转换
4. 界面：下载页列出所有版本，显示版本号、类型、发布时间
5. 筛选：正式版 / 快照 / 远古版；搜索框按版本号过滤

**产出**：打开「下载」页，能看到全部 900 多个版本，能筛选能搜。

---

## M3 · 下载引擎

**目标**：能可靠地把一堆文件下下来。

**步骤**
1. `src/main/downloader.js`：并发下载队列（默认 8 个并发）
2. 先下到 `.part` 临时文件，**校验 SHA1 通过后才改名**成正式文件
3. 失败自动重试（最多 3 次，间隔递增）
4. 已存在且校验通过的文件**直接跳过**（共享文件不用重下）
5. 实时上报：已完成数 / 总数、速度、剩余时间
6. 支持暂停 / 取消
7. 镜像切换：连续几个文件都慢于阈值 → 换镜像

**产出**：能下单个文件、显示进度和速度、断网重试、校验不通过自动重下。

**注意**：这一步不碰游戏，只把"下载"这件事本身做扎实。

## M4 · 安装一个版本

**目标**：点一个版本 → 真的把它装到硬盘上。

**步骤**
1. 下载版本 JSON，解析出需要哪些文件
2. **先摸清 Java 运行时怎么下载**（这是本里程碑最大的未知数）
3. 装客户端 jar
4. 装 libraries（几十个 jar）
5. 解压 natives 到版本目录
6. 装 assets（几千个小文件，最耗时）
7. 全部完成后，把版本写进"已装版本"列表
8. 界面：下载页每个版本有「安装」按钮；显示整体进度

**产出**：选一个版本点安装 → 进度条走完 → 版本出现在列表里。

**注意**：Java 那一步如果接口走不通，**立刻降级**为"让用户手动指定 Java 路径"，
不要卡在这里。

---

## M5 · 启动游戏 ⭐（整个项目的验收关口）

**目标**：**真的能进游戏。**

**步骤**
1. `src/main/accounts.js`：离线账号（名字 + 离线 UUID 算法）
2. `src/main/launch.js`：拼装启动参数
   - classpath = 所有 libraries + client.jar
   - 替换版本 JSON 里的占位符
3. 起 Java 进程，**抓它的输出**
4. 界面：左侧账号栏能填名字；点「开始游戏」启动
5. 失败时把游戏的报错翻译成中文提示 + 常见原因

**产出**：填个名字 → 点开始游戏 → **游戏窗口起来、能进世界**。

**这是第一期的核心关口**：如果游戏真的起来了，说明
"下载 → 安装 → 参数拼装 → Java"整条链路全对了。

## M6 · 版本管理

**目标**：把"版本"这件事管起来。

**步骤**
1. 已装版本列表（区分哪个是当前选中的）
2. 版本设置页：改版本名、改版本描述
3. 快捷打开四个文件夹：版本 / 存档 / Mod / 截图
4. 启动设置：内存分配（显示本机内存 + 限制上限）、窗口大小、
   版本隔离、进程优先级、游戏目录
5. 删除版本（**二次确认**，且要说明删的是什么）

**产出**：能像 PCL 那样管理每个版本。

## 每个里程碑的固定收尾动作

做完任何一个里程碑，**必须**按顺序完成：

1. `npm start` 跑一遍，确认没有报错
2. 按 `docs/05-验收标准.md` 里对应的清单**逐条实际测**并打勾
3. 更新 `docs/05-验收标准.md` 的勾选状态
4. 更新本页的「进度总览」
5. 写当天 `开发日志/YYYY-MM-DD.md`
6. Git 提交一次快照
7. **停下**，向用户汇报（说清"你现在能看到什么"），等确认再进下一个
