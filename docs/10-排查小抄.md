# 排查小抄（毛球）

> 这张表原来长在 `CLAUDE.md` 里。2026-10-10 搬出来的原因很实在：**它太长了，
> 而 CLAUDE.md 每开一个新会话都要整份读一遍** —— 相当于每次都花钱读一遍这张表。
> 现在它躺在这儿，**要用的时候才读**。
>
> 用法：遇到怪问题、或者要动下载 / 启动 / 打包 / 版本这些地方，**先来这儿翻一眼**；
> 自己踩了新坑，也往下面那张表里加一条（现象 → 原因/处理，附上当时怎么发现的）。

> 这一栏会随着开发不断追加。**每踩一个坑就记一条**。

| 现象 | 原因 / 处理 |
|---|---|
| `npm start` 报 `Cannot read properties of undefined (reading 'xxx')` | 环境变量 `ELECTRON_RUN_AS_NODE` 在作怪。`scripts/start.js` 已自动清掉它 |
| **测打包好的 exe 时"一闪就退/双击没反应"** | **还是 `ELECTRON_RUN_AS_NODE`！** 从这个开发环境里启动**任何** Electron 程序，它都会被当成"普通 Node"跑然后**立刻退出（退出码 0、没有任何输出、系统日志里也没崩溃记录）**——看起来像"打包坏了"，其实程序好好的。2026-10-07 为此白查了半小时。**正确姿势**：PowerShell 里先 `$env:ELECTRON_RUN_AS_NODE = $null` 再启动；bash 里用 `env -u ELECTRON_RUN_AS_NODE`。**用户自己双击图标不受影响**（资源管理器启动时环境是干净的） |
| **`npm install` 显示成功，但 `npm start` 报 `Electron failed to install correctly` 或 `fetch failed`** | Electron 分两步装：npm 包装上了，但它还要**另外从 GitHub 下载 200 多 MB 的主程序**，这一步在国内经常失败，而且**失败得很隐蔽**（npm 照样报成功）。项目里的 `.npmrc` 已配好国内镜像。若仍失败，手动跑：`npx install-electron`（带 `ELECTRON_MIRROR` 环境变量更保险）。装好的标志是 `node_modules/electron/dist/electron.exe` 存在（约 240 MB） |
| npm 每次运行都提示 `Unknown project config "electron_mirror"` | 那是 npm 不认识这两行配置（它们是给 electron 包读的，不是给 npm 读的）。**只是警告，不影响使用** |
| 打包到最后一步报 `connect ETIMEDOUT` | electron-builder 要从 GitHub 下 NSIS 编译资源，国内连不上。用 `npm run dist`（走 `scripts/build.js`，已内置国内镜像） |
| **用中文进程名查进程查不到** | bash 传 UTF-8、Windows 工具收 GBK，中文名对不上会**静默匹配失败**，看起来像"没这个进程"。查进程用非中文办法：按 PID、按可执行文件路径 |
| **下载地址换成镜像后 404** | 镜像不是简单换域名：**库文件要加 `/maven`、资源文件要加 `/assets`**，其余同路径。完整映射表见 [docs/02-技术方案.md](docs/02-技术方案.md) 的决策 3 |
| **下载拿到空内容，却显示"成功"** | Node 的 `https.get` **不会自动跟随 302 跳转**。Mojang 和镜像都会跳转，不处理就会拿到空响应。`src/main/http.js` 里已实现跟随，别绕开它直接用 `https` |
| **用探测脚本跑 Electron 时数据跑到别的目录了** | 探测脚本没调 `app.setName()`，`app.getPath('userData')` 会用默认名（`%APPDATA%\Electron`）。要么在脚本里也调一下 setName，要么记得清理那个目录 |
| **抓到的游戏日志是一堆 XML 标签** | 那是 log4j 给**官方启动器**解析用的控制台格式，不是出错。游戏自己写的 `logs\latest.log` 是纯文本（`[时间] [线程/级别]: 消息`）。界面显示时会自动翻译成纯文本，存盘的日志保持原样 |
| **界面怎么是英文的** | 游戏默认语言就是英文（`options.txt` 里的 `lang:en_us`）。游戏里 Options → Language 可改；本机已改成 `lang:zh_cn`。以后要让启动器**首次启动自动设成中文**，记得先加进需求文档 |
| **离线模式日志里有 401 / Realms 授权失败** | **正常现象**，不是故障。离线模式没有正版令牌，游戏去问 Mojang 用户信息就会 401。不影响单机游玩，别去"修"它 |
| **启动参数里的 `natives/java`、`natives/lwjgl` 这些子目录** | 1.19 起游戏把动态库放进 classpath，**自己在运行时解压**到这些子目录；启动器只要建好目录。老版本才是"启动器解压 natives"那套，两套逻辑都在 `launch.js` 里 |
| **安装清单里漏了日志配置文件** | 版本 JSON 的 `logging.client` 指向一个 log4j 配置文件（约 1 KB），M4 的安装清单没包含它，M5 改成**启动前检查、缺了补下**（`launch.js` 的 `ensureLogConfig`）。装新版本时不用管 |
| **启动游戏后弹出"需要使用新应用以打开此 ms-gamingoverlay 链接"** | **跟启动器无关**，是 Windows 游戏栏（Game Bar）被禁用/卸载后，游戏想调它调不到。点「确定」即可，不影响游戏 |
| **开了版本隔离后，游戏里看不到原来的世界** | 正常现象：隔离后游戏目录变成 `versions\<版本号>\`，游戏只看那里的 saves。老存档在 `.minecraft\saves` 里**没丢**，搬进版本目录就能看到（见 docs/05 M6.2 一节） |
| **"我设过中文了"这件事要按目录记** | 配置里存的是 `languageAppliedDir`（目录路径）而不是"是/否"：开了版本隔离后游戏目录会变，得对新目录重新设一次，否则游戏又变回英文 |
| **在输入框打字时弹出一个"词建议"小框** | **不是软件的问题，是 Windows 系统的"文本建议"**。实测证据：打 `Test` 弹的是 Test/Tested/Testified/Testimony 这种**词典补全**（浏览器自动填充只会显示你输过的词）。想关掉：Windows 设置 → 设备 → 输入 → "当我键入时显示文本建议"。代码里 `autocomplete="new-password"` 只是顺手防浏览器那层，压不住系统这个 |
| **装到一半取消/失败的版本** | 目录里可能有版本 JSON 和 jar 了，看着像装好了。装的过程中会写一个 `.incomplete` 标记文件，**有它的版本一律不算装好**（`paths.isVersionInstalled` 会返回 false），界面上显示成「安装」而不是「已安装」，重装会补齐 |
| **删下载的文件时** | 库文件和资源文件是**所有版本共用**的！删之前必须核对"别的已装版本还要不要它"（见 `install.dropPartialInstall` 的 `collectReferencedFiles`）。实测删了 1032 个文件后，26.3 的 74 个库 + 5147 个资源一个没少 |
| **装了 Mod 加载器的版本"没有客户端 jar"** | 这是正常的！它写着 `inheritsFrom: "26.3"`，用原版那份 jar。所以"装好了吗"的检查**不能只认自己的 jar**（`paths.isVersionInstalled` 会顺着继承往上找）。M10 实测踩过：Fabric 装完了却不出现在版本列表里 |
| **拿 `fabric-loader-x-y` 去社区网站搜 Mod** | 社区网站（Modrinth）**只认游戏版本号**（26.3），不认加载器版本号。搜之前要顺着 `inheritsFrom` 还原（`main.js` 的 `resolveGameVersion`） |
| **下 Mod 时要按加载器筛** | 不筛的话会下到别的加载器的构建（实测：Fabric 版本下到了 NeoForge 版的 Sodium，**跑不起来**）。`versions.loaderName()` 认加载器，`main.js` 的 `loaderSlugFor` 转成 Modrinth 的写法 |
| **Fabric 官方服务器在国内极慢** | 实测：接口 20 秒、库文件 30 秒都下不完；**BMCLAPI 镜像了它**（`bmclapi2.bangbang93.com/fabric-meta/…` 和 `/maven/…`），分别 1.2 秒和 0.2 秒。`loaders.js` 默认走镜像、官方兜底；`mirror.js` 里有 `maven.fabricmc.net → /maven` 的映射 |
| **关掉启动器，正在玩的游戏也没了** | Electron 把子进程放在同一个"进程组"（job object）里，主进程一退**整组被杀**。修法：`spawn` 时加 `detached: true`（`launch.js` 里已加，注释写明了原因）。实测：杀掉启动器进程，游戏照跑 |
| **Forge / NeoForge 的官方仓库连不上** | `maven.minecraftforge.net` 20 秒超时、`maven.neoforged.net` 直接失败。**BMCLAPI 全都有**：`/forge/minecraft/<版本>`（构建列表）、`/neoforge/list/<版本>`、`/maven/...`（文件）。`mirror.js` 里有这两个域名的映射 |
| **BMCLAPI 的 Forge 构建列表里那个 `hash` 不能拿来校验安装器** | 实测：它和安装器文件的 SHA1、MD5 **都对不上**（八成是它元数据里别的东西）。所以下安装器时不校验（`forge.js` 里注释写明了）；装完的库文件都带官方哈希，照样验 |
| **装 Forge / NeoForge 必须"打补丁"** | 版本文件的 classpath 上有个 `...-client.jar`（像 `forge-26.3-66.0.2-client.jar`），**哪里都下载不到**——要用安装器里带的"处理器"拿原版 jar 现场生成。不做的话启动直接报"有 1 个游戏文件不在了"。实现在 `forge.js` 的 `runPatchers` |
| **探测脚本卡住、一行输出都没有** | 两个原因：① 它和**正开着的软件抢同一个数据目录**（Electron 会锁）→ 探测脚本换一个 `app.setName('毛球-测试')` 就好；② Node 的 `console.log` 在重定向到文件时**会缓冲**，进程没退出就看不到 → 探测脚本里用 `fs.appendFileSync` 写日志 |
| **Windows 压缩包里的中文文件名全是乱码** | Windows 自带的"压缩成 zip"**用系统编码（GBK）写文件名，而且不标 UTF-8 标志**；按 ZIP 规范该按 CP437 解 → 乱码。`zip.js` 里已改成：没标 UTF-8 的名字按 GBK 解 |
| **压缩包里的路径是反斜杠**（`我的世界\level.dat`） | 也是 Windows 自带压缩干的，不符合 ZIP 规范但确实存在。`zip.js` 读取时统一换成正斜杠，别的地方才好处理 |
| **测到的是旧版本** | 打包成 exe 之后，**桌面图标跑的是"装好的那份"**，不跟着源码变。做完新功能如果不重新 `npm run dist` + 装一遍，测到的还是老版本（2026-10-07 实际踩过：拖放功能做完后用户拖文件没反应，因为桌面那个还停在 M8）。**规矩：每做完一个能看见的功能，顺手重打包 + 重装**。**注意：开发模式也一样**——`npm start`/双击 .bat 起来的窗口，**页面已经加载完了，改源码它不会自己变**（2026-10-08 用户连问三次"还没改好"，就是因为他一直开着旧窗口）。**改完必须让用户"完全关掉再打开"**，而且**毛球有关窗口 ≠ 退出**（有托盘），要右键托盘图标退出 |
| **拖进来的整合包装好了、一启动就崩** | 十有八九是 **Java 版本不对**。整合包走的是"拖放装"这条路，它**不下 Java**；以前启动器会从"本机已有的运行时"里随便抓一个顶上，版本对不上游戏当场崩（实测：1.20.1 Forge 的包要 Java 17，抓了 Java 16，报 `UnsupportedClassVersionError`——用户看不懂的英文）。**现在两处都修了**：`java.js` 的 `findJava` 优先挑大版本号对得上的；`launch.js` 启动前发现版本要求的运行时不在，会自动补下（`install.ensureJavaComponent`） |
| **Git Bash 把以 `/` 开头的参数当路径吞掉** | 不止安装包那一次。**任何** `/XXX` 形式的 Windows 参数都会中招：实测 `taskkill /PID 28824 /F` 被吃成 `C:/Program Files/Git/PID`，报"无效参数"、进程杀不掉。**解法**：命令前面加 `MSYS_NO_PATHCONV=1`，或者写成双斜杠 `//PID` |
| **命令行静默装安装包，装完找不着程序 / 装到怪地方** | 两个坑叠在一起（2026-10-07 白折腾了一刻钟）：① **Git Bash 会把 `/S`、`/D=C:\xxx` 这类参数搞坏**——反斜杠被当成转义吃掉，于是 `/D=C:\Users\某某\...` 变成 `C:SERS<Ľ�ǚ�ǔ�ƈ�Ő�>...`，程序装进一个叫 `C:SERS<Ľ�ǚ�ǔ�ƈ�Ő�>AppDataLocalProgramsmc-launcher` 的怪目录。② **electron-builder 的安装程序把"上次装到哪"记在注册表 `HKCU\SOFTWARE\<安装包GUID>\InstallLocation` 里**，一旦装歪一次，**往后每次安装都跟着歪**（还会先把上一份卸掉，于是"越装越没有"）。**正确姿势**：把安装包复制到一个**纯英文路径** → 写个**纯英文 .bat**（内容就一行 `setup.exe /S`，别带 `/D`）→ 用 `cmd /c` 跑那个 .bat（绕开 bash 的参数转换）。装歪了先清残留：删 `HKCU\SOFTWARE\<GUID>`、`HKCU\...\Uninstall\<GUID>`、桌面那个指向不存在文件的快捷方式，再重装。**用户自己双击安装包不受影响**（图形界面里默认路径是对的） |
| **探测脚本里连开好几个窗口截图，第一张之后就没动静了** | Electron 默认**关掉最后一个窗口就退出整个程序**。脚本 `win.destroy()` 之后进程已经在收拾东西准备走了，后面几个窗口压根没开出来（退出码还是 0，看着像"跑完了"）。**解法**：脚本开头加一句 `app.on('window-all-closed', () => {})` 兜住 |
| **`win.loadFile('某个中文名.html')` 报 `ERR_FAILED (-2)`** | 探测脚本里生成的临时 HTML **文件名别用中文**（内容里中文没问题）。改成 `cmp0.html` 这种纯英文名就好了 |
| **探测进程卡住了，怎么只杀自己那几个** | 别用 `taskkill /F /IM electron.exe` 按名字全杀——**会把别人开着的 Electron 程序一起干掉**。先认人：`MSYS_NO_PATHCONV=1 wmic process where "name='electron.exe'" get processid,commandline /format:csv`，命令行里带 `.probe/xxx.js` 的就是自己的，拿到 PID 再 `taskkill /PID <id> /T /F`。**另一条线索**：打包版叫「毛球.exe」，所以 `electron.exe` 只可能是开发模式/探测脚本 |
| **改了界面布局后，自己做的"对比图"整行错位** | 裁软件截图时**别忘了顶栏那 48px**。布局一动，之前记死的坐标全部作废——**重新量一遍再裁** |
| **控制台刷 `Error sending from webContents: Render frame was disposed`** | 窗口正在关的那一瞬间，`webContents` 还在但里面的**渲染帧已经释放**了，这时 `send()` 会让 Electron 自己往控制台喷红字——**JS 的 try/catch 拦不住**（是 C++ 层打的）。窗口关掉时把定时器停掉（`mainWindow.on('closed', ...)`），并且发送前连 `webContents.mainFrame.detached` 一起检查 |
| **无边框窗口里，自己画的按钮点上去没反应** | 顶栏声明了 `-webkit-app-region: drag` 之后，**那块区域里的鼠标事件是被系统吃掉的**，按钮必须自己声明 `-webkit-app-region: no-drag` 才点得动。另外：去掉系统边框后拖窗口、双击最大化、贴边分屏**都还是系统给的**（不用自己写），但"现在是不是最大化"得自己同步——监听 `maximize`/`unmaximize` 推给界面 |
| **临时截图窗口开到比屏幕还宽，图右边缺一块** | Windows 会把窗口**压回工作区宽度**（1920 的屏幕 ≈ 1904），多出来的部分照不到，而且**不会报错**——看起来就是"图被裁了"。要更大的画布，就把图先 `resize` 小一点再拼，别指望窗口无限宽 |
| **两个毛球一起开，界面里的图片加载不出来** | 开发版和"装好的那份"共用 `%APPDATA%\毛球\`，里面那个 `Cache` 文件夹**同一时间只允许一个程序用**。后启动的会刷一屏 `Unable to create cache 拒绝访问`，而且**图片会加载不出来**——2026-10-08 实测：首页大启动卡那张风景图直接消失、只剩渐变底色，**看起来就像"这个功能没做"**（就是这么以为的）。**已修**：`main.js` 里 `if (!app.isPackaged)` 时把 `disk-cache-dir` 指到 `%TEMP%\毛球-dev-cache`（配置和账号仍然共用，只有缓存分开） |
| **关掉窗口后进程还在，托盘里留着图标** | 毛球有托盘，所以**关窗口 ≠ 退出程序**——进程会一直在后台，占着 `%APPDATA%\毛球\`（包括那个 Cache）。排查"缓存被谁锁着"时先想到它：`MSYS_NO_PATHCONV=1 wmic process get processid,executablepath` 看还有几个 |
| **想确认 exe 里嵌的图标对不对，`app.getFileIcon()` 读出来是"白色文档"默认图标** | **那是它读错了**——`getFileIcon` 走的是系统关联/缓存，不是文件里真正嵌的资源。2026-10-08 为此差点以为"图标压根没嵌进去"。**换 PowerShell 读**：`[System.Drawing.Icon]::ExtractAssociatedIcon('路径')` 然后 `.ToBitmap().Save(...)`。（跑 .ps1 用 `powershell -File xxx.ps1` 就行，这台机器默认策略是 RemoteSigned、本地脚本能跑，**不需要加 `-ExecutionPolicy Bypass`**） |
| **静默卸载装好的毛球** | 安装目录里的 `Uninstall 毛球.exe` —— 注意 **Git Bash 会把 `/S` 参数搞坏**，得写 `MSYS_NO_PATHCONV=1 "./Uninstall 毛球.exe" /S`。**卸载不会删用户数据**（`package.json` 里 `deleteAppDataOnUninstall: false`），账号/配置/备份/游戏目录都不动 |
| **静默安装** | 安装包**别在中文路径下直接跑**，也别写 `setup.exe /S` 的 .bat 靠"当前目录"找文件（实测 cmd 的工作目录不一定是那个）。最省事的一条：`MSYS_NO_PATHCONV=1 cmd /c "D:\英文路径\setup.exe" /S`。装哪儿由**注册表里记着的上次位置**决定，不是安装包说了算 |
