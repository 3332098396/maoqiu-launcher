**关于"功能还没做"这件事怎么处理**

这一版页面内容是空的。为了让用户一眼看懂"哪些能用、哪些还没做"：

- 每个页面顶部有一条**蓝色提示条**，写明"这是布局预览，功能会从 M? 开始做"
- 内容区列出**这一页以后会有什么**（账号、开始游戏、下载进度……），
  让人对最终形态有预期
- 左边栏里凡是还没做的按钮**一律置灰**（`disabled`），鼠标移上去也不反应

**为什么不先放一堆能点但没用的东西**：那会让人以为软件坏了。
宁可明确告诉用户"还没做"，也不要给一个点了没反应的按钮。

      所以这段逻辑没被真正跑过

**关于 Java 运行时接口（计划里标记的最大未知数）**

开工第一件事就是摸它，摸清楚了：

1. `launchermeta.mojang.com/v1/products/java-runtime/<启动器版本号>/all.json`
2. 里面按平台分类，找 `windows-x64` → 版本 JSON 里指定的那个组件（如 `java-runtime-epsilon`）
3. 组件条目里有 `manifest.url` → 再取一份文件清单（411 个文件）
4. 文件地址在 `piston-data.mojang.com`（**已有镜像映射**）

**顺带发现能复用**：Java 运行时的目录格式是 `runtime\<组件名>\bin\java.exe`，
和用户机器上已有的完全一致，所以**已经下过的 Java 会直接跳过**（省 100 MB）。
实测用户机器上的 `java-runtime-alpha` 和 `delta` 就被识别并跳过了。

**注意**：中间那串"启动器版本号"是**写死在地址里**的。万一 Mojang 换编号会 404，
所以整段逻辑包了 try/catch，拿不到 Java 就降级为"先装游戏文件，
启动时再让用户手动指定 Java 路径"。

**一个重要发现（写下来免得以后困惑）**

`[时间] [线程/级别]: 消息` 的纯文本格式，和 latest.log 一致。

**顺手修掉的一个真问题**

装到一半取消（或断电/失败）的版本，目录里可能已经有版本 JSON 和客户端 jar 了，
光看这两个文件会以为"装好了"——其实资源还差一半，启动起来会缺音效缺贴图。
现在装的过程中会插一个 `.incomplete` 标记，**有标记的版本一律不算装好**，
界面上显示成「安装」而不是「已安装」，重装会把剩下的补齐。
