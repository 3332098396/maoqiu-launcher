# 05 · 验收标准

> **这份文档是干什么的**
> 它规定"每个里程碑做到什么程度才算做完"。
> 做完一个里程碑，就照着对应清单**逐条实际测一遍**，不许凭印象打勾。
>
> 用法：把 `[ ]` 改成 `[x]` 表示通过。发现问题就在后面加一行注明。

## M1 · 界面骨架

**验收时间**：2026-10-07
**结论**：✅ 通过

- [x] 顶栏有三个导航按钮：启动 / 下载 / 设置，居中摆放
- [x] 点每个按钮都能切到对应页面，当前页是白底胶囊，一眼看得出
- [x] 每个页面都是"左边一栏 + 右边内容区"的结构
      —— 左侧栏的内容**按页面各不相同**（跟 PCL 一样）：
      启动页放账号和启动按钮、下载页放资源分类、设置页放设置分类
- [x] 窗口缩到最小尺寸（860×560）布局不乱，内容都能看全
- [x] 配色是渐变淡蓝，看着舒服不刺眼
- [x] 按钮、菜单这类基础样式统一

**关于"功能还没做"这件事怎么处理**

这一版页面内容是空的。为了让用户一眼看懂"哪些能用、哪些还没做"：

- 每个页面顶部有一条**蓝色提示条**，写明"这是布局预览，功能会从 M? 开始做"
- 内容区列出**这一页以后会有什么**（账号、开始游戏、下载进度……），
  让人对最终形态有预期
- 左边栏里凡是还没做的按钮**一律置灰**（`disabled`），鼠标移上去也不反应

**为什么不先放一堆能点但没用的东西**：那会让人以为软件坏了。
宁可明确告诉用户"还没做"，也不要给一个点了没反应的按钮。

## M2 · 版本清单

**验收时间**：2026-10-07
**结论**：✅ 通过

- [x] 打开「下载」页，能看到版本列表
      —— 实测拉到 **918 个**版本，状态栏显示"共 918 个版本 · 最新正式版 26.3"
- [x] 每个版本显示：版本号、类型徽章、发布时间
      —— 版本号用等宽字体（1 和 l 不会看错），类型用不同颜色区分
- [x] 筛选「正式版 / 快照 / 远古版」各自正确
- [x] 搜索框输入版本号能过滤
      —— 实测：选「正式版」+ 搜 "1.20" → 显示"显示 7 / 918 个版本"，
      结果全是 1.20.x 的正式版
- [x] 「刷新」按钮能强制从网上更新
- [x] **缓存生效，断网也能看上次的列表**
      —— 用探测脚本直接验证：没有缓存时联网取（800ms），
      有缓存时**只读本地、3ms 返回，根本不碰网络**（快 266 倍）
- [x] 列表滚动流畅

**未实测**：真正的"拔网线"场景没模拟（那要改系统网络设置，太侵入）。
但缓存读取路径已经证实**完全不碰网络**，所以断网时能出列表是成立的。
真断网时后台更新会失败并提示"更新失败，继续用上次的列表"，已有的列表不会被清空。

**顺带确认的一件事**：镜像的地址映射规则**实测出来了**（见 docs/02 的表格）。
不是简单换域名——库文件要加 `/maven` 前缀、资源文件要加 `/assets` 前缀，
直接换域名会返回 404。这几条在动代码前就用真实地址逐个验证过。

## 发现问题怎么记

验收时发现任何不对劲，**不要当场改代码**，先记下来：

1. 追加到当天 `开发日志/YYYY-MM-DD.md` 的"发现的问题"一节
2. 写清楚：**什么现象 / 怎么复现 / 期望是什么**
3. 如果是需求理解错了，改 `docs/01-需求说明.md`
4. 改完代码后，回到这份清单，**把相关项重新测一遍**
