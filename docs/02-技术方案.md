# 02 · 技术方案

> **这份文档是干什么的**
> 它记录"这个软件是用什么做的、为什么这么做"。
> 如果看到某段代码觉得莫名其妙，答案通常在这里。
>
> **人话总结**：启动器的本质是——**下载一堆文件，把它们摆到正确的位置，
> 然后拼一条正确的命令把 Java 跑起来**。界面是外壳，下载和启动才是核心。

---

## 一、技术选型

| 部位 | 用了什么 | 为什么选它 | 代价 |
|---|---|---|---|
| 程序外壳 | **Electron 44** | 与「历史粘贴板」同版本，用户机器上已跑通；界面用网页技术写，想多好看都行 | 安装包较大 |
| 界面 | 原生 HTML + CSS + 原生 JS | 不需要构建步骤，源文件直接能看懂能改 | 复杂交互写起来啰嗦 |
| HTTP 请求 | Node 内置 `https` | 只需要下载文件和取 JSON，不值得引入第三方库 | 要自己处理重定向、超时 |
| 下载调度 | **自己写**（见决策 1） | 需要并发 + 断点续传 + 哈希校验 + 镜像切换，现成库都不太贴合 | 代码量比用库多 |
| 哈希校验 | Node 内置 `crypto`（SHA1） | Mojang 的清单里每个文件都带 SHA1，直接比对 | — |
| 解压 | Node 内置 `zlib` + 自写 ZIP 读取 | 只有 natives 需要解压，量很小，不值得引入库 | 要自己解析 ZIP 结构 |
| 配置存储 | JSON 文件 | 同「历史粘贴板」的做法：可读、可备份、零依赖 | 数据量极大时会慢（我们不会） |
| 打包 | electron-builder → NSIS | 已跑通，`scripts/build.js` 直接复用 | 打包要几分钟 |

**运行时不引入任何第三方依赖。** 这对一个非程序员维护的项目很重要——
依赖越少，坏掉的概率越小，出了问题也越好查。

## 二、架构：三层

```
┌─────────────────────────────────────────────────────────┐
│  渲染层（界面）  src/renderer/                           │
│  只负责显示和上报点击，碰不到系统，碰不到硬盘             │
│  通过 window.api.xxx() 向主进程要数据、下命令             │
└───────────────────────┬─────────────────────────────────┘
                        │  IPC
┌───────────────────────▼─────────────────────────────────┐
│  安全桥  src/preload/preload.js                          │
│  一张"白名单"：界面能做的事全部列在这里，逐条放行         │
└───────────────────────┬─────────────────────────────────┘
                        │  IPC
┌───────────────────────▼─────────────────────────────────┐
│  主进程  src/main/                                       │
│  mojang.js     版本清单、版本 JSON、资源地址              │
│  mirror.js     官方 ↔ 国内镜像的地址转换                  │
│  downloader.js 下载引擎：并发、重试、校验、进度            │
│  java.js       找 Java，找不到就下                        │
│  install.js    装一个版本：jar / libraries / assets       │
│  launch.js     拼启动参数、起进程、抓日志                  │
│  accounts.js   账号（离线 UUID 计算）                     │
│  paths.js      所有目录路径，集中一处                      │
│  settings.js   配置读写（原子写入）                        │
└─────────────────────────────────────────────────────────┘
```

**为什么这么分**：界面是程序里最"危险"的地方（要显示各种外部内容）。
只要界面碰不到系统，它就算出问题也伤不到用户的电脑。
`contextIsolation: true` + `nodeIntegration: false` 这两行是**安全底线，不许改**。

## 三、关键技术决策

### 决策 1：下载引擎自己写

市面上的下载库要么只下单个文件、要么不支持"下完之后按哈希校验并自动重试"。
而我们的需求很具体：

```
输入：一份文件清单 [{ 地址, 保存到哪里, SHA1, 大小 }, ...]（可能几千条）
要求：
  · 同时下 8 个
  · 每个下完立刻校验 SHA1，不对就重下
  · 失败自动重试（最多 3 次，间隔递增）
  · 已经下好且校验通过的文件跳过（下次装同一个版本的共享文件就不用重下）
  · 实时报告总进度、速度、剩余时间
  · 能暂停 / 能取消
  · 官方源太慢自动换镜像，镜像失败再换回来
```

这套逻辑自己写出来大概两百行，比把现成库掰弯要省事，也更好排查。

### 决策 2：装一个版本要下哪些东西

| 内容 | 大致体量 | 说明 |
|---|---|---|
| 客户端 jar | ~20 MB | 主程序，一个文件 |
| libraries | ~150 MB | 几十个 jar，清单在版本 JSON 里 |
| **assets** | **300~800 MB** | **几千个小文件**（音效、语言、贴图），最耗时 |
| Java 运行时 | ~50 MB | 版本 JSON 里指定需要哪个 Java 大版本 |
| natives | 少量 | libraries 里带 `natives` 标记的要解压到版本目录 |

**注意**：libraries 和 assets 是**所有版本共享**的——装第二个版本时，
大部分文件已经在了，校验一下跳过即可，所以会快很多。

### 决策 3：镜像怎么切

官方域名 → BMCLAPI 对应路径的映射（五类：版本清单、版本 JSON、数据文件、
资源文件、库文件）。策略：

1. 默认走官方源
2. **连续几个文件都慢于阈值**（比如 200 KB/s）→ 本次任务切换到镜像
3. 镜像也失败 → 切回官方
4. 每个文件各自记账，不搞"全局一刀切"

**已实测**：两个源的版本清单**逐字节一致**（同为 277504 字节、918 个版本），
可以放心替换。

### 决策 4：Java 自己下载，不靠用户装

用户机器上**没有独立安装 Java**（查过了）。而 MC 必须有 Java 才能跑。
好在 Mojang 官方提供各版本的 Java 运行时，启动器可以按版本 JSON 里
声明的 `javaVersion.component` 自动下载对应的那一个。

**降级**：如果自动下载失败，允许用户在设置里**手动指定 Java 路径**。

### 决策 5：启动参数怎么拼

版本 JSON 里声明了 `mainClass`、`arguments.jvm`、`arguments.game`，
里面有 `${auth_player_name}` `${version_name}` `${game_directory}` `${assets_root}`
这类占位符，逐个替换即可。classpath = 所有 libraries + client.jar。

**离线模式的三个关键值**：
| 参数 | 离线时填什么 |
|---|---|
| 玩家名 | 用户自己填 |
| UUID | 用官方离线算法算：`nameUUIDFromBytes("OfflinePlayer:" + 名字)` |
| accessToken | 任意字符串（离线服务端不校验） |

### 决策 6：跨局域网联机走 EasyTier（第二期）

**不自己造轮子。** EasyTier 是开源免费的异地组网软件，原理是
"先打洞直连，连不上再走中继服务器"，PCL 2 的联机功能用的就是它。

启动器要做的是：下载 EasyTier 核心 → 生成配置 → 拉起进程 → 显示连接状态。
难点不在代码，在**要求管理员权限装虚拟网卡**，以及**中继节点是社区贡献的**。

## 四、数据存放在哪

| 内容 | 位置 | 说明 |
|---|---|---|
| 启动器配置 | `%APPDATA%\MC启动器\config.json` | 账号、设置 |
| 游戏文件 | `%APPDATA%\.minecraft\`（可改） | **与官方启动器同格式**，标准布局 |
| ├ versions | 每个版本一个子目录 | 版本 JSON + jar + natives |
| ├ libraries | 共享的库文件 | 所有版本共用 |
| ├ assets | 共享的资源文件 | 所有版本共用 |
| ├ saves | 存档 | 版本隔离时各自独立 |
| └ mods / resourcepacks / shaderpacks | Mod、资源包、光影 | |

**为什么游戏目录要用英文路径**：老版本的 Java 和部分 Mod 对中文路径处理不好，
容易报莫名其妙的错。所以游戏目录默认放 `%APPDATA%\.minecraft`（纯英文），
只有启动器自己的配置目录用了中文名。

## 五、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **Java 运行时下载接口需现场确认** | 装不了 Java 就启动不了游戏 | M4 开工第一件事就是把它摸清楚；摸不通就降级为"手动指定 Java 路径" |
| assets 有几千个小文件 | 下载慢、容易卡死 | 并发 8 个 + 逐个校验 + 失败重试；进度按"已完成文件数"算 |
| 首次安装要下 500 MB~1 GB | 用户以为卡死了 | 全程显示进度、速度、剩余时间；可暂停可取消 |
| 国内直连 Mojang 慢 | 体验差 | 官方 + BMCLAPI 自动切换（已实测镜像与官方一致） |
| 中文路径让老版本 Java / Mod 出错 | 游戏起不来 | 游戏目录默认英文路径 |
| 游戏启动报错对新手极不友好 | 用户不知道哪错了 | 抓游戏输出，翻译成中文 + 常见原因清单 |
| 内存设太大把电脑卡死 | 系统级问题 | 读本机总内存，自动限制上限并给建议值 |
| 安全软件误删下载的 jar | 游戏起不来 | 校验失败时明确提示"可能是杀毒软件删了文件" |
| 联机功能要管理员权限 | 用户可能点了拒绝 | 解释清楚为什么需要，拒绝了也能正常玩单机 |
| 联机中继节点不稳定 | 连不上或卡顿 | 界面显示"当前是直连还是中继"；连不上时给出手动方案 |

## 六、目录职责速查

| 路径 | 放什么 | 谁负责 |
|---|---|---|
| `src/main/` | 主进程：下载、安装、启动、配置 | 只在这里碰系统和硬盘 |
| `src/preload/` | 安全桥，白名单式暴露能力给界面 | 每加一个功能，这里加一条 |
| `src/renderer/` | 界面 | **不许**在这里直接调用系统能力 |
| `assets/` | 图标等静态资源 | — |
| `build/` | 打包用的图标和安装脚本 | — |
| `docs/` | 标准文档 | 改需求先改这里 |
| `开发日志/` | 每天一份工作记录 | 每次开发结束前更新 |
